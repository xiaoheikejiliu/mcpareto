# McPareto

**不推荐你吃什么，只算给你看：菜单上哪些选项在数学上已经没有存在的理由。**

[在线演示](https://xiaoheikejiliu.github.io/mcpareto/) · [MCP 集成说明](MCP_INTEGRATION.md) · [开发记录](workbuddy.md)

麦记菜单越做越长，几十上百个餐品同时摆着。这个工具把整份菜单投影到「价格 × 收益」的平面上，求帕累托前沿，然后告诉你两件事：

1. 哪些餐品是**帕累托最优**的——没有任何其他选项能在不比它贵的前提下给得更多；
2. 哪些餐品**被支配**了——存在另一个餐品比它便宜、给得还不少于它。对这类选项，理性决策者没有选择的理由。

第二类是重点。基于真实门店数据的实测里，被支配的餐品占比在 **61% 到 85%** 之间，取决于你把什么当作「收益」。

## 它和「性价比排行榜」有什么不同

排行榜回答「第一名是谁」。但它答不了两个更实际的问题：

> 我常点的那个，到底被谁比下去了？差多少？
>
> 除了榜首那几个，剩下的里面还有哪些是纯粹的浪费？

排行榜里第 40 名和第 3 名看起来只是名次差距，实际上前者可能被后者**全面碾压**——更贵、热量更低、蛋白质更少。帕累托支配能识别这件事，排序不能。

## 快速开始

零依赖，不需要 pip install 任何东西，Python 3.10+ 即可。

```bash
# 1. 先看效果（用仓库内的演示样本）
python3 scripts/build_web.py
open docs/index.html

# 2. 换成你所在门店的真实数据
export MCD_MCP_TOKEN="在 open.mcd.cn/mcp 控制台领取"
python3 scripts/collect.py --address "深圳北站" --out data/menu.json
python3 scripts/build_web.py --data data/menu.json
open docs/index.html
```

产出的 `docs/index.html` 是**单文件应用**：数据、样式、脚本全部内联，没有外部请求，可以直接双击打开、丢进任意静态托管、或者发链接给别人。图表是手写 SVG，不依赖任何图表库。

跑测试：

```bash
python3 -m unittest discover -s tests -v
```

## 三种视角

同一条菜单，换一条收益轴，前沿的形状完全不同——这个差异本身就是结论。

| 视角 | 纵轴 | 含义 |
|---|---|---|
| 吃饱优先 | 热量 kcal | 同样的钱，谁给的热量更多 |
| 蛋白质优先 | 蛋白质 g | 同样的钱，谁给的蛋白质更多 |
| 控盐优先 | 钠 mg | 同样的钱，谁的钠负担更小 |

一个餐品在「蛋白质优先」视角下可能稳稳站在前沿上，换到「控盐优先」立刻变成劣解。所以「哪个最划算」这个问题没有唯一答案，只有「在你看重的那条轴上」。

产品里刻意不给出综合评分。把多个维度压成一个分数需要人为指定权重，那个权重不该由工具替用户决定。

## 为什么不是「每元蛋白质」排序

第一版的设计确实是把价格和「每元蛋白质」作为两个维度。这是个方法论错误：价格已经内含在「每元」的分母里，两个维度不独立，前沿会退化成一个点。

正确的做法是拿**绝对收益**对价格做权衡。代码里保留了每元指标，但只作为详情面板里的辅助说明，不参与前沿计算。这个修正记录在 `src/mcpareto/models.py` 的注释里。

## 项目结构

```
mcpareto/
├── src/mcpareto/
│   ├── models.py        # 领域模型、指标轴、三种视角的定义
│   ├── pareto.py        # 支配判断、前沿求解、分层、碾压者检索
│   ├── normalize.py     # MCP 异构返回 → 领域模型（含单位对齐）
│   └── mcp_client.py    # 零依赖 MCP Streamable HTTP 客户端
├── scripts/
│   ├── collect.py       # 从 MCP 采集真实菜单、营养、实付价
│   └── build_web.py     # 计算并编译成单文件 HTML
├── web/template.html    # 页面模板（手写 SVG，无图表库）
├── docs/index.html      # 构建产物，单文件应用，可直接由 GitHub Pages 托管
├── data/sample_menu.json# 演示样本，13 项
└── tests/               # 112 个单元测试（pareto / normalize / mcp_client）
```

## 数据来源与诚实声明

- **真实数据全部来自麦当劳中国官方 MCP**（`mcp.mcd.cn`），项目不内置、不推断任何营养数值。
- 仓库里的 `data/sample_menu.json` 是**演示样本**，13 项，取自公开报道中麦当劳中国官方 MCP 的实测数据（门店 1420227，2026-10-16）。它只用于让页面在没有 Token 的情况下也能跑起来，页面顶部会显示醒目提示。完整门店数据请自行运行 `collect.py`。
- 该样本中脂肪、碳水、钙三项在原报道里没有给出，因此留空为 `null`，**没有估算填充**。缺失维度在计算时会被跳过，不会当成 0。

## 已知边界

- 前沿计算是 O(n²)。158 个餐品约 2.5 万次比较，毫秒级；上千项时才需要考虑空间索引。
- 只处理单品之间的比较。套餐的营养是否为各组成项之和、能否直接与单品比较，取决于 MCP 返回的口径，本项目不做合并或拆分推断。
- 价格有效期取决于采集时刻。麦当劳的菜单和价格随时变，`data/menu.json` 里的数据是一次快照，页面上会标注采集时间。
- 不考虑口味、品牌偏好、出餐速度、门店库存波动。这个工具只处理能在数据上被证明的部分。
